أساسيات Core Web Vitals: ما تحتاج قياسه فعلًا

شرح مبسط للمؤشرات الثلاثة التي يقيس بها جوجل تجربة صفحتك الفعلية، مع الحدود الجيدة وطريقة القياس الصحيحة.

قبل أن تُحسّن أي شيء في موقعك، تحتاج أن تعرف ماذا تقيس بالضبط. Core Web Vitals هي ثلاثة مؤشرات تعتبرها جوجل أساسية لتجربة الصفحة، وهي نفسها التي تظهر في تقارير Search Console وأدوات القياس.

لماذا تهم هذه المؤشرات؟

لأنها تقيس شيئًا يشعر به الزائر فعليًا: متى رأى المحتوى، متى استجابت الصفحة لضغطته، وهل كانت العناصر تقفز أمامه أثناء القراءة. تحسينها ليس ترفًا تقنيًا — إنه تحسين مباشر لتجربة الزائر.

المؤشرات الثلاثة

LCP — سرعة أكبر عنصر ظاهر

يقيس الزمن حتى ظهور أكبر عنصر محتوى في الشاشة الأولى — عادة صورة رئيسية أو عنوان كبير. الحد الجيد: 2.5 ثانية أو أقل. أشهر أسباب بطئه: صور ثقيلة بلا ضغط، وخطوط تؤخر الظهور.

INP — استجابة التفاعل

يقيس مدة استجابة الصفحة للنقر واللمس ولوحة المفاتيح عبر جلسة المستخدم كاملة. الحد الجيد: 200 مللي ثانية أو أقل. السبب الشائع: مهام JavaScript طويلة تحجب الخيط الرئيسي.

CLS — ثبات التصميم

يقيس مجموع الإزاحات غير المتوقعة للعناصر. الحد الجيد: 0.1 أو أقل. أشهر الأسباب: صور وإعلانات دون أبعاد محجوزة، وخطوط تستبدل النص متأخرًا.

كيف تقيس بشكل صادق

  1. PageSpeed Insights — يمنحك بيانات الحقل والمختبر معًا.
  2. تقرير Core Web Vitals في Search Console — صورة الموقع ككل عبر الزمن.
  3. Lighthouse — تشخيص مفصل في المختبر بعد كل تعديل.

بيانات الحقل تخبرك بما يعيشه المستخدمون فعلًا؛ بيانات المختبر تخبرك أين تبحث عن المشكلة. لا تكتفِ بواحدة منهما.

مثال عملي سريع

أحد أشهر أسباب CLS هو الصور دون أبعاد محددة:

<img src="hero.webp" alt="وصف الصورة"
     width="1200" height="630"
     decoding="async">

تحديد width وheight يمنح المتصفح نسبة الأبعاد مسبقًا، فيحجز المساحة قبل تحميل الصورة.

المؤشرما يقيسهالحد الجيد
LCPسرعة ظهور أكبر عنصر محتوى≤ 2.5 ثانية
INPزمن استجابة التفاعلات≤ 200 مللي ثانية
CLSمقدار الإزاحات البصرية≤ 0.1

الخلاصة

ابدأ بالقياس قبل أي تحسين، وركز على المؤشر الأضعف لديك. للتواصل المباشر زر الموقع الرئيسي، أو تصفح بقية المقالات. المرجع الرسمي الكامل: web.dev/vitals.
